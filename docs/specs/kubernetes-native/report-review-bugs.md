## Verdict

Memory management on the normal and error paths is correct (no leak, no double-free, no UAF found; ownership is moved correctly across start/stop/join and across the `conf.c` reload swap). The real defects are in data/edge-case correctness: a negative uptime at startup produces an out-of-range `startTimeUnixNano`, and the OTLP failure classification mislabels several status classes.

### Memory-management review (checked, no defect found)

- `otel_metrics__config_add_header` (`otel_metrics.c:302-313`): on key/value alloc failure both are freed and `header_count` is not incremented; the one-slot-larger array is still owned by `cfg->headers` and freed by cleanup — no leak, no double free. `mosquitto_realloc` does not free the old block on failure (`libcommon/memory_common.c:239-282`), so the unchanged `cfg->headers` stays valid.
- `otel__config_copy` (`otel_metrics.c:357-386`) zeroes `dest` first, frees `dest->endpoint` before returning `NOMEM` from the calloc branch, and calls `config_cleanup` on the strdup branch (the calloc'ed array makes partially filled entries NULL-safe for `mosquitto_free`) — no leak/double free.
- `otel_metrics__encode_json` error paths (`otel_metrics.c:243-250`, and the early `cJSON_Delete(root)` branches at `:207`,`:219`) delete the correct disjoint set of nodes; the `dp` node is not also attached before the failure check.
- `otel__post` always reaches `curl_slist_free_all`/`mosquitto_free(url)` on every path, and `response.body` ownership transfers to the caller which frees it (`otel_metrics.c:608-611`).
- Start/stop ordering (`otel_metrics.c:680-751`) is sound: `otel_service_version`/`otel_instance_id`/`otel_runtime_config` are freed only after `pthread_join`, and `otel_stop`/`otel_runtime_config` are only touched by the worker under `otel_mutex` or before `pthread_create`.
- Reload swap in `conf.c:746-751` (`config_cleanup(&dest->otel); dest->otel = src->otel; src->otel = (struct otel_config){0};`) moves ownership correctly and prevents a double free by config_reload's own cleanup; the exporter keeps its private copy, so no UAF.
- `http_api.c` lost its local `struct metric`/`extern` and now gets both from `sys_tree.h` (included at `http_api.c:36`) — no duplicate-definition / ODR break; `struct metric` is declared with `static`-less external linkage in `sys_tree.c:51`.

## Good practices / strengths

- `WITH_OTEL` is contained: default OFF in `config.mk` and `src/CMakeLists.txt`, requires `WITH_SYS_TREE` (FATAL_ERROR / `$(error)`), `src/Makefile`'s unconditional `otel_metrics.o` compiles to an empty TU, and the zero-overhead harness (`mosquitto/test/otel/zero-overhead.sh`) pins symbol/dependency/config-surface containment.
- Credential hygiene: `otel__sanitize_endpoint` strips `user:password@` before logging (`otel_metrics.c:650-677`) and the header values are never logged.
- `curl_easy_setopt(CURLOPT_NOSIGNAL, 1L)` (thread-safety in the broker process) and `CURLOPT_TIMEOUT` are set; the export thread is the only curl user.
- Atomic storage for cross-thread metric reads is documented as non-snapshot-consistent; the design decision (deferred reload with an explicit warning) is honest rather than silently broken.
- The unit test pins the classification table to the real `$SYS` topic set by compiling `sys_tree.c` in (`test/unit/otel/otel_metrics_test.c`), catching drift.

## Open questions / unverified

1. **§5.2 spec text not in repo.** The code repeatedly cites "(§5.2 failure mapping)" (`otel_metrics.c:340`, `otel_metrics.h:124`) and `test/broker/24-otel-otlp-metrics.py:5`; no `§5.2` exists in `docs/specs/kubernetes-native/spec.md` (§5 is "pending" per its register). The 429/3xx classification in B3 is therefore judged against general OTLP semantics, not a repo-controlled requirement — confirm whether `429`/`204`/`3xx` are specified as retryable.
2. **`_Atomic double` lock-freedom** on the maintained 32-bit targets is unverified (see the performance report, P3); `__atomic_is_lock_free` was not evaluated at runtime here.
3. **First-export timing** (immediate export before `mosquitto_main_loop`) — whether an empty/zero first batch reaching a collector is acceptable was not verified against the spec's intent for G-C2.1.
4. **B1 flakiness reproduction** — reasoned from the code order (`mosquitto.c:457` → `sys_tree.c:183` → `otel_metrics.c:711`); not reproduced in a live run (no build/test executed).
